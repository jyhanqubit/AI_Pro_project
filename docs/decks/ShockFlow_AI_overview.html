Background — 배경 / 문제

Bike-share 운영의 손실 대부분은 stockout(품절)과 overflow(dock 초과)에서 나옵니다. rider가 자전거를 못 찾으면 trip과 신뢰를 잃고, dock이 넘치면 rebalancing 트럭 비용이 발생합니다.

특히 event·교통 장애·날씨 같은 irregular demand shock에 기존 예측은 취약하고, "LLM/뉴스로 개선했다"는 주장은 검증 없이 과장되기 쉽습니다. ShockFlow AI는 shock를 구조화된 신호로 바꾸고, 그 가치가 실제로 있는지를 측정하는 데 초점을 둡니다.

Business — 사업 포인트

  • 1운영비 절감 — 더 정확한 forecast → shortage/overflow·트럭 이동 비용 감소.
  • 2LLM 가치의 이익 환산 — event/LLM feature 효과를 LLM 비용을 제한 profit 순가치로 정량화.
  • 3Operator Decision Copilot — 근거 기반 자연어 질의(숫자 hallucination 0).
  • 4Rider trip planner — 대여·반납 station + 도보를 계산해 안내.

Differentiation — 차별성

  • 1End-to-end 추적성 — Article→Event→H3Zone→Feature→forecast delta→action 전 구간 provenance. black box 없음.
  • 2Temporal correctness — available_at ≤ forecast_cutoff 엄수, leakage 방지 회귀 테스트(14:01→14:00).
  • 3Honesty 계약 — claim_status taxonomy + ResultEnvelope, artifact 기반 완성, null도 정직 보고, 수치·인과·양자우위 과장 금지.
  • 4LLM 경계 — LLM은 event structuring·routing·explanation만. 숫자는 typed tool에서만 나옴.
  • 5Graph가 실제 기여 — Neo4j event graph → numeric forecasting feature (시각화 장식 아님).
