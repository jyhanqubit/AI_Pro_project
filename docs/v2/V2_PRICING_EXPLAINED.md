# V2-05 쉽게 읽기 — 탄력성 · Surge · A/A 실험

이 문서는 V2-05(동적 가격)의 결과를 **비전문가도 이해할 수 있게** 풀어 쓴 설명서입니다.
수식·측정값의 원본은 `V2_PRICING.md`와 `reports/v2/pricing/`에 있습니다. 모든 수치는
**`simulated`**(실사용자 없는 그림자 시뮬레이션)이며 인과·매출 주장이 아닙니다.

---

## 1. 가격탄력성 (price elasticity of demand)

"가격을 바꾸면 수요가 얼마나 반응하나"를 나타내는 계수입니다.

```
e = (수요 변화율 %) / (가격 변화율 %)
```

- 부호는 항상 **음수**: 가격이 오르면 수요는 내려감(수요의 법칙).
- 크기가 반응의 세기:
  - `|e| < 1` → **비탄력적(inelastic)**: 가격에 둔감(필수재 성격).
  - `|e| > 1` → **탄력적(elastic)**: 가격에 민감(사치재 성격).

우리가 쓴 값은 **`e = -0.3`** (가정, `config/v2/assumptions.yaml`):

```
가격 10% ↑  ⇒  수요 3% ↓   (0.3 × 10%)
```

즉 **가격을 올려도 손님은 조금만 빠집니다.** 출근용 자전거는 "지금 가야 하는" 상황이라
요금이 조금 올라도 대부분 그냥 이용 → 비탄력적. 이 값은 측정값이 아니라 **가정**이므로
`sensitivity.json`에서 0.5×·1×·2×로 흔들어 결과가 뒤집히지 않는지 확인합니다.

## 2. Surge (할증 가격)

자전거가 **부족할 것 같은 지역**에서 가격을 잠깐 `m`배로 올리는 것. 수요 공식:

```
D(m) = D × (1 + e·(m − 1))
```

예: 기본 수요 D=100, m=1.25(25% 할증), e=−0.3
```
D(1.25) = 100 × (1 + (−0.3)(0.25)) = 100 × 0.925 = 92.5   → 손님 7.5%만 감소
```

Surge가 노리는 두 효과:

- **효과 A — 수요를 덜어 품절 완화.** 재고 20대인데 수요 100이면 80이 품절. 살짝 할증해
  수요를 낮추면 품절 압력이 준다.
- **효과 B — 남는 자전거당 마진 ↑.** 어차피 재고(20대)만 빌려주는데, 그 20대를 1.25배
  요금으로 빌려주면 매출이 오른다.

원장 목적식:
```
net(m) = min(D(m), 재고) × 마진 × m   −   품절수량 × 품절비용
         └ 덜 팔지만 비싸게 ┘              └ 놓친 수요 페널티 ┘
```

### 왜 576번 중 15번만 발동됐나

"surge가 손해라서"가 아니라 **부족 상황 자체가 드물어서**입니다:
- 시나리오에서 재고는 보통 ~20대, 시간당 수요는 대개 그보다 작음 → 품절 위험 없음 →
  그냥 base 요금.
- 아침 피크 + 노이즈로 수요가 재고를 넘는 **드문 순간(~15번)** 에만 "지금 진짜 부족" →
  surge 발동.

### 가드레일(안전장치)과의 연결

- 아무리 부족해도 `m ≤ 1.5` (상한) → **바가지 방지** (G1)
- **안전사고 지역엔 surge 금지** (G6) → 위급 상황에 돈 더 받는 것을 원천 차단
- 이득이 base보다 확실할 때만 발동 (G3), 크레딧 총액은 예산 이내 (G4)

감사(`guardrail_audit.json`)는 이 규칙들을 **모든 행동에 대해** 검사해 위반 수를 셉니다(=0).
일부러 9.9배 같은 불법 행동을 심어 감사가 잡아내는지도 확인(**네거티브 컨트롤**)해서, 검사가
"통과 도장"이 아니라 실제로 작동함을 증명합니다.

## 3. A/A 실험이란 (왜 "효과 0"이 성공인가)

A/A는 **처리효과를 재는 게 아니라 "측정기 자체가 편향 없나"를 확인**하는 절차입니다.

> 비유: 저울 두 개(A·B)에 **똑같은 물건**을 올렸는데 무게가 다르게 나오면 저울이 고장 난 것.
> A/A는 양쪽에 **완전히 동일한 정책**을 적용하고 "차이가 0으로 나오나"를 봅니다.

결과: 효과 ≈ 0, 95% 신뢰구간(CI)이 0을 포함 → **측정 설계가 편향 없이 정상**. 진짜 가격효과를
재는 A/B는 실사용자가 필요한데 없으므로 하지 않음 → 그래서 `simulated`.
